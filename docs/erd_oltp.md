# OLTP entity relationship diagram

Operational database `university`, schema `public`. The reasoning behind the model is in [design_oltp.md](design_oltp.md).

Every primary key is a `bigint GENERATED BY DEFAULT AS IDENTITY` column. Every table also has `created_at` and `updated_at` (`timestamptz`); they are left out of the diagram for readability. `UK` marks a column that is part of a unique business key.

The simulation clock `sim.clock` lives in a separate schema and has no relationships; it is described in [design_generator.md](design_generator.md).

```mermaid
erDiagram

    faculties ||--o{ professors : employs
    programs ||--o{ courses : contains
    programs ||--o{ student_programs : "is studied in"
    students ||--|{ student_programs : "belongs to"
    courses ||--o{ course_prerequisites : requires
    courses ||--o{ course_prerequisites : "is required by"
    courses ||--o{ course_offerings : "is offered as"
    semesters ||--o{ course_offerings : schedules
    professors ||--o{ course_offerings : teaches
    students ||--o{ enrollments : makes
    course_offerings ||--o{ enrollments : receives
    course_offerings ||--o{ exam_terms : holds
    enrollments ||--o{ exam_attempts : "is graded by"
    exam_terms ||--o{ exam_attempts : records

    faculties {
        bigint faculty_id PK
        text name UK
        text code UK
    }

    programs {
        bigint program_id PK
        bigint faculty_id FK
        text name UK
        text degree_level UK "bachelor | master"
        smallint duration_semesters
        smallint total_ects
    }

    students {
        bigint student_id PK
        text index_number UK
        text first_name
        text last_name
        text email UK
        date date_of_birth
        text gender "female | male | other"
        text city
        smallint enrollment_year
        text status "active | graduated | dropped_out | suspended"
        timestamptz graduated_at "set exactly when graduated"
        timestamptz dropped_out_at "set exactly when dropped out"
    }

    student_programs {
        bigint student_program_id PK
        bigint student_id FK, UK
        bigint program_id FK
        date valid_from UK
        date valid_to "NULL while current"
        text reason "enrollment | transfer"
    }

    professors {
        bigint professor_id PK
        bigint faculty_id FK
        text first_name
        text last_name
        text title "lecturer | assistant_professor | associate_professor | full_professor"
        text email UK
    }

    courses {
        bigint course_id PK
        bigint program_id FK
        text code UK
        text name
        smallint ects "1 to 15"
        smallint semester_number
        boolean is_mandatory
    }

    course_prerequisites {
        bigint course_prerequisite_id PK
        bigint course_id FK, UK
        bigint prerequisite_course_id FK, UK "differs from course_id"
    }

    semesters {
        bigint semester_id PK
        smallint academic_year UK "start year, 2023 = 2023/24"
        text term UK "winter | summer"
        date start_date
        date end_date
    }

    course_offerings {
        bigint offering_id PK
        bigint course_id FK, UK
        bigint semester_id FK, UK
        bigint professor_id FK
        smallint capacity
    }

    enrollments {
        bigint enrollment_id PK
        bigint student_id FK, UK
        bigint offering_id FK, UK
        timestamptz enrolled_at
        text status "enrolled | passed | failed | withdrawn"
    }

    exam_terms {
        bigint exam_term_id PK
        bigint offering_id FK, UK
        date exam_date
        text term_type UK "january | february | june | july | september"
    }

    exam_attempts {
        bigint attempt_id PK
        bigint enrollment_id FK, UK
        bigint exam_term_id FK, UK
        smallint points "0 to 100"
        smallint grade "5 to 10"
        timestamptz attempted_at
    }
```

## Cardinalities

| Relationship | Cardinality | Enforced by |
|---|---|---|
| faculty → programs, professors | one to zero or many | FK |
| program → courses, student_programs | one to zero or many | FK |
| student → student_programs | one to one or many | FK; "at least one" is guaranteed by the writing application, not the database |
| course → course_prerequisites (both sides) | one to zero or many | two FKs, unique pair |
| course, semester, professor → course_offerings | one to zero or many | FK; one offering per course and semester |
| student, course offering → enrollments | one to zero or many | FK; one enrollment per student and offering |
| course offering → exam_terms | one to zero or many | FK; one term of each type per offering |
| enrollment, exam term → exam_attempts | one to zero or many | FK; one attempt per enrollment and term |
